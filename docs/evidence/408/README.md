# 验收欠账 #408：安装链人工验收证据

用正式发布的 1.6.1 安装包，在纯净 Windows 10 测试机上补做 #408 的安装链人工验收：净机安装冒烟与安装向导视觉走查。对应 Issue：[#408](https://github.com/marci-labs/LabelFrame/issues/408)。

**结论**：清单 6 项里 2 项通过、3 项部分通过、1 项不通过。发现 5 项安装包缺陷（见「发现的问题」），已另立 Issue，都还没有修复。

## 轮次

每轮是一条轮次链：开机前自检（物料摘要与签名、全部走查在本机对替身对话框演练、汇总脚本的对照）→ 还原基线、开机 → 复制物料、客机脚本逐步执行 → 取回安装日志 → 还原、关机。

| 轮次 | 步骤（依次） |
|---|---|
| 客户端轮 | ① 提权启动客户端向导，全新安装到完成页（对照）。② 普通方式启动客户端向导，全新安装到完成页，点「完成」。③ 重启，看托盘自启。④ `msiexec /x`：答「否」、答「是」。⑤ `msiexec /i {code} REMOVE=ALL`：不勾、勾选（本轮作废，见「取证过程本身的问题」二）。⑥ 不勾自启全新安装后重启（本轮作废，同上）。⑦ 重跑安装包，在维护向导里选「删除」 |
| 服务端轮 | ① 没有运行时：两个包的缺运行时对话框，点链接。② 静默安装。③ `msiexec /x` 答「是」。④ `REMOVE=ALL` 勾选（本轮作废），再装后重跑安装包（这一步暴露了问题 5）。⑤ 重跑安装包，在维护向导里选「删除」 |
| 补充轮 | ① 客户端静默安装，重启，看托盘与用户数据。② `REMOVE=ALL` 不勾。③ 再装，静默重跑一遍，启动客户端。④ `REMOVE=ALL` 勾选。⑤ 不勾自启全新安装后重启。⑥ 服务端静默安装，`REMOVE=ALL` 不勾。⑦ 再装，`REMOVE=ALL` 勾选。⑧ 再装，静默重跑一遍 |
| 升级轮 | ① 没有运行时：两个包的缺运行时对话框（点链接被 Windows 自己的页面挡住，本轮作废）。② 普通方式启动服务端向导，全新安装。③ 服务端 1.6.0 静默安装，改配置，1.6.1 覆盖升级；`REMOVE=ALL` 不勾。④ 再装，`REMOVE=ALL` 勾选。⑤ 客户端 1.6.0 静默安装，启动并写配置，1.6.1 覆盖升级，重启；`REMOVE=ALL` 不勾。⑥ 再装并启动，`REMOVE=ALL` 勾选 |
| 链接轮 | ① 给测试账户关掉 Windows 的「你即将完成电脑设置」页。② Server、Client 的缺运行时对话框各走一遍：鼠标点链接，没反应时用键盘回车，最后用系统方式打开同一地址作对照 |
| 点击轮 | 同链接轮，鼠标点第二下之后才试键盘 |

轮次记录（`*-round.txt`）里每一行是客机脚本的一行输出，带宿主机侧的时间戳。

## 发现的问题

五项都是 1.6.1 正式包在纯净 Windows 10 上的实测结果，各自另立了 Issue，都没有修复。

1. **安装向导完成页勾选「立即打开 LabelFrame」，点「完成」后客户端不启动**（[#498](https://github.com/marci-labs/LabelFrame/issues/498)）。两种启动方式各复现一次。安装日志里安装本身返回 0，启动动作 `LaunchClientOnExit` 返回 1631；之后没有客户端进程，53960 不监听，只有更新服务在运行（`client-round.txt` 步骤 10、15；`installer-log-excerpts-client.txt`）。
2. **卸载时「是否同时清除本程序产生的用户数据」的询问，在用户走得到的卸载路径上不出现**（[#499](https://github.com/marci-labs/LabelFrame/issues/499)）。「应用和功能」的卸载（`msiexec /x`）只有系统的「你确定要卸载此产品吗？」；重跑安装包的维护向导也不经过询问页。询问页只在命令行 `msiexec /i {code} REMOVE=ALL` 时出现，且它后面的页面用的是安装措辞，进度页先显示「正在安装」再变成「正在删除」（截图 `client-ready-page-after-the-question.png`、`client-progress-page-while-removing.png`）。
3. **缺运行时对话框里的下载链接，鼠标点击不打开**（[#500](https://github.com/marci-labs/LabelFrame/issues/500)）。对话框在前台，指针点在链接文字上，链接控件拿到了键盘焦点，40 秒内没有浏览器进程也没有浏览器窗口；再点一下还是这样。把焦点放在链接上按回车，Edge 在 10 秒内打开「下载 .NET 10.0」页面。同一台机器上用系统方式打开同一地址也正常（`summary-link.txt`、`summary-click.txt`；截图 `link-desktop-after-the-mouse-click.png`、`link-desktop-after-enter-on-the-link.png`）。两个包相同。说明：点击是取证脚本注入到测试机桌面的指针点击，不是真人鼠标；真人点击的表现需要有人确认一次。
4. **勾选「清除用户数据」卸载客户端后，日志文件还在**（[#502](https://github.com/marci-labs/LabelFrame/issues/502)）。两次结果一致：`%LOCALAPPDATA%\LabelFrame\logs\` 下的 `app-<日期>.log`、`serilog-self.log` 留下，`C:\ProgramData\LabelFrame\Client` 留下一个空目录；其余（三个数据库、`host-*.log`、`connection.json`、`settings.json`、客户端的 `appsettings.json`）都被删除（`summary-all.txt` 的 A48，`all-round.txt` 步骤 27 之后的状态；`summary-upgrade.txt` 的 U59，`upgrade-round.txt` 步骤 65 之后的状态）。
5. **服务端已安装并在运行时，静默重跑一遍 Server MSI，服务被停掉，不再启动**（[#501](https://github.com/marci-labs/LabelFrame/issues/501)）。干净场景下复现：安装 → 服务就绪 → 不带参数再运行一次 `msiexec /i <包> /qn`（返回 0）→ 60 秒内服务没有起来，状态是 Stopped，53961 不通（A66、A67）。安装日志：没有任何功能需要变更（`Feature: MainFeature; Installed: Local; Request: Null`），无条件的 `StopServerService` 执行了，后面的标准动作 `StartServices` 没有可启动的服务。

## 取证过程本身的问题

都不在产品里，是取证脚本与排期自身的缺陷。每一处都在对应结论定稿之前改掉并重测；这里记下哪些记录不能直接用。

**一、第一遍两轮整体作废。** 托盘图标的读取有假阳性（提示文字里的换行让解析失败，失败信息又混进了返回值），点链接的坐标落在链接文字之外的空白处，浏览器观察有缺陷。第一遍的记录没有入库；第二遍（客户端轮、服务端轮）起用的是改过的走查。

**二、第二遍里有两组场景作废，由补充轮与升级轮重测。** `REMOVE=ALL` 场景里，走查以为询问页之后是维护向导，遇到安装包自己的确认页就取消了；「不勾自启后重启」因此是在产品还装着的状态下跑的。所以 `summary-client.txt` 的 C31、C32、C34、C36、C40–C43 和 `summary-server.txt` 的 S31、S33 不通过，不能当作产品结论；这两组的结论取自补充轮（A42–A44、A50–A52）与升级轮（U44–U48、U55–U59）。

**三、补充轮的记录带一条走查备注。** `REMOVE=ALL` 流程里进度页先显示「正在安装」，走查把它当成意外窗口记了一条（`summary-all.txt` 的 A42、A44、A47、A61、A64 因此不通过）。卸载本身完成了，状态文件与安装日志可用；升级轮用修正后的走查重测了这四个场景。

**四、安装类走查的安装日志没有落在日志目录。** 第二遍里以 `/i` 启动的走查把安装日志写到了 `C:\Probe\` 下（路径少一个分隔符），轮末的取回看不到它们。这些日志是用另一个只读的取回脚本在虚拟机还原之前单独取回的（`installer-log-excerpts-client.txt`、`…-server.txt` 里对应日志的行号指向它们）。之后的轮次改了路径，日志随轮取回。

**五、「缺运行时」的走查三次才做成。** 第二遍点了链接，链接控件拿到了焦点，但没有等到浏览器，记录不足以说明原因（问题 3 最早的两次观察）。补充轮把这两条走查排在了运行时安装之后，对话框根本没有出现，`summary-all.txt` 里 R1、R2 开头的项不通过是这个原因；那一轮里用系统方式打开同一地址的对照记录仍然有效。升级轮里 Windows 在登录几分钟后用全屏的「你即将完成电脑设置」页盖住了桌面，指针点击落在那一页上，当时的走查还不认得这一页（`summary-upgrade.txt` 的 U1c、U2c 不通过是这个原因，那一轮的整屏截图都是这一页，没有入库）。链接轮先给测试账户关掉这一页，才拿到干净的记录；点击轮又确认了第二下点击。

**六、问题 5 最先是在服务端轮的步骤里偶然看到的。** 第四步取消后产品还装着，第五步的「再装」实际是在已安装的服务端上重跑。补充轮第八步用干净场景复现。

**七、汇总脚本被真实证据纠正了几处。** 状态文件里自启项不存在时写的是 `RUN_KEY present=False`，不是编造证据里用的 `absent`；卸载前的用户文件数要在客户端退出之后再数（运行时还多出共享内存与日志文件）；对话框页的按钮数要只数那一页；「全中文」在没有记录到任何文字时不能算通过；没点链接时浏览器起来了也不能算链接的功劳。每一处改动后都重跑了对照（`summary-controls.txt`）。

**八、客户端轮的基线状态采晚了。** 客户端轮的第一份状态是在运行时安装之后采的，所以 C01 不通过（里面有已装运行时的记录）。没有安装任何东西之前的基线由服务端轮的 S01、升级轮的 U01 与链接轮的 L01 给出。
