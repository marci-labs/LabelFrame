# #408 补记：用正式 1.6.2 包在用户本机重走安装向导（2026-11-27）

上一份证据（[上级目录](../README.md)）是用正式 1.6.1 包在纯净测试机上取的，发现的 5 项安装包缺陷已在迭代 181（[#504](https://github.com/marci-labs/LabelFrame/issues/504)）修复并随 v1.6.2 发布。这里是在用户自己的电脑上，用正式发布的 1.6.2 客户端包把安装向导重新走一遍：一遍是真实的升级（1.6.0 → 1.6.2），一遍是重跑安装包看卸载前的询问页。对应 Issue：[#408](https://github.com/marci-labs/LabelFrame/issues/408)。

**结论**：两段走查共 40 项检查全部通过（升级 20 项、询问页 20 项）。向导各页全中文，「开机自动启动」与「立即打开 LabelFrame」都默认勾选，点「完成」后客户端以不提权身份启动；作业、模板与各份配置文件原样保留；卸载前有询问页，「上一步」回得到类型页。没有改动的：机器上装的客户端现在是 1.6.2（走查本身就是一次真实升级）。

## 走查一：经向导从 1.6.0 升级到 1.6.2（`summary-upgrade.txt`，20 项全过）

运行正式包，向导按全新安装的页面走（检测到已装的旧版本，安装时替换）：

欢迎 → 许可 → 安装目录（只读）→ 安装选项（「开机自动启动」默认勾选）→ 准备安装 → 点「安装」→ UAC 提示（用户点是，约 5 秒）→ 进度页 → 完成页（「立即打开 LabelFrame」默认勾选）→ 点「完成」。

- 安装日志：提权同意后执行，安装包先结束运行中的客户端（`ShutdownWinHost`），再移除旧版本（`RemoveExistingProducts`）；服务端与客户端的引擎线程都返回 0；点「完成」时启动动作 `LaunchClientOnExit` 返回 1（`installer-log-excerpts.txt`）。
- 点「完成」后：客户端进程立即出现，是不提权身份；窗口出现，托盘图标由客户端注册；本机接口应答。
- 升级后：登记版本 1.6.0 → 1.6.2，程序文件版本 1.6.2.0，产品版本 `1.6.2+d618e09`（即 tag 指向的提交）；运行中的客户端自报 1.6.2，设备号不变。
- 保留情况：作业历史 100 条、模板 3 个，接口返回的列表内容与升级前逐字节一致；打印机连接文件、打印设置、机器级设置、安装目录下的配置文件哈希不变；开机自启项还在；更新服务在运行。数据库文件被运行中的客户端独占、读不到哈希，记录的是升级前的副本哈希与前后大小。

## 走查二：重跑安装包，看卸载前的询问页后取消（`summary-peek.txt`，20 项全过）

维护欢迎 → 更改 / 修复 / 删除 → 选「删除」→ 询问页「是否同时清除本程序产生的用户数据」→ 按一次「上一步」回到类型页 → 再选「删除」回到询问页 → 取消 → 确认取消 → 向导已中断 → 完成。

- 询问页有「上一步」「继续」「取消」，「清除用户数据」默认不勾选（截图 `shots/peek-03-ClearData.png`）。
- 安装日志里只有界面页，没有执行序列；安装程序以 1602（用户取消）退出。
- 前后状态逐项一致：登记的产品与服务、程序文件、开机自启项、机器级设置、用户目录、监听端口、四个可读的数据与配置文件、接口返回的作业与模板；运行中的客户端没有被结束或重启。

## 取证过程本身的问题

都不在产品里。

**一、升级走查在进度页停早了，完成页由续走脚本接着走完。** 移除旧版本的那一段，进度页的状态栏显示「正在删除快捷方式」，页面标题仍是「正在安装 LabelFrame Client」；走查脚本按状态栏把这一段认成了卸载页，记录「意外窗口」后停了下来，安装本身没有受影响。完成页在屏幕上停留约两分钟后，由续走脚本（`walk-finish-result.txt`）读复选框、点「完成」并观察客户端启动。判定脚本只在「走查自带的失败项恰是这一条、续走结果为完成」时才算通过（`summary-upgrade.txt` 的 H01）。

**二、升级走查的截图只截到每页的左上部分。** 这台电脑的显示有缩放，不感知缩放的进程只看得到缩小后的坐标，截图被裁掉右侧与下侧的按钮区（`shots/upgrade-0*.png`）。询问页走查前把截图线程设为感知缩放，`shots/peek-*.png` 是完整的。升级走查每一页的控件文字有完整记录（`walk-upgrade-result.txt`），所以页面内容不受影响，只是那几张截图不完整。

**三、判定脚本错过四处，都在复核时发现并改正**：把「tag 指向的提交」的七个字符与完整的提交号比较；把模板的个数当成接口状态码；按 UTF-8 读 UTF-16 的安装日志；在「完整界面下日志不写安装结果行」的包上要求那一行。另有一步状态记录取早了（安装还在收尾时），重新取了一次。最终结果以改正后的脚本为准；两个判定脚本各做了反向对照（把登记版本改回 1.6.0、把连接文件的大小改掉、把「上一步」改成不存在、把结果改成已卸载），对应的项恰好不通过。

**四、走查脚本为这台电脑改了三处**：安装过程中的消息框只记录、留给人来答，不替用户点；点「安装」后等提权提示的时间从 4 分钟放宽到 15 分钟；不再自动关闭或强制结束留下来的安装程序。
