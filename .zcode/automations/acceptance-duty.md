# 验收轮值定时任务——创建说明

> 生成：2026-09-11，由迭代管理轮值会话创建（LabelFrame 自动迭代模式试点）。
> 背景：平台限制一个会话只能绑定一个定时任务；「迭代管理轮值」（每 20 分钟，管 `自动执行` / `进行中` / `验收不通过` 标签）已占用一个会话。本任务为第二个轮值，需在**新会话**中创建。
> **修订 v2（2026-09-11）**：用户确认验收分工协议（A/B/C 分级 + 委托结项）。
> **修订 v3（2026-09-11）**：值守改为「指挥官」模式——每轮只做扫描 / 分级 / 派单 / 回收检查 / 汇报，取证与结项交后台 worker（自包含 prompt 全流水线）；新增标签 `验收中`（Issue 级锁，60 分钟无心跳回收）与 `验收不通过`（返修回流迭代轮值，其 prompt 已同步更新）；资源规则：真机 / 真实客户端类 worker 同时 ≤1；结项审查：A 类先关后审，判断取舍类公示 ≥4h。
> **修订 v4（2026-09-11）**：两轮值定时任务 prompt 改为**指针式**——触发时读取本文件「协议全文」执行；修订本文件即于下次触发生效。结项审查简化：取消「拟结项公示 ≥4 小时」窗口，一律先关后审。定时任务的创建 / 删除 / 排期调整仍需在对应会话中人工操作。
> **修订 v5（2026-09-11）**：结项 PR 的**检查等待与合并不得占用值守会话**——建 PR 后立即派后台 watcher（轮询检查 → 全绿 squash 合并 → 关联 Issue 关闭与标签清理 → 回报；红 / 超时回报；master 前进致合并被拒时 update-branch 重试一次），值守 / 陪验收尾派单后即结束本轮。
> **修订 v6（2026-09-17）**：worker 自建 worktree 用毕回收——验收 worker 如自建 worktree（取证 / 结项 PR），流水线终点 `git worktree remove --force` 并确认目录消失，残骸 rm -rf 补删（与沙箱实例「用毕清理」同款纪律）；漏网残骸由迭代轮值每轮对账兜底（见 [iteration-duty.md](iteration-duty.md) v7）。起因：wt55-accept / wt57-accept / wt-accept-ui / wt55-reverify 等验收残骸累积。
> **修订 v7（2026-09-20，当前生效）**：结项即清本地证据目录——worker 流水线关闭关联 Issue 时同步删除主仓 `artifacts/` 下本轮对应的证据目录（`accept-<N>*` 等），前提＝关键证据已以 Issue 评论 / 附件留存 GitHub（可溯后本地即删）；主仓 `artifacts/` 残留对账由迭代轮值 v8 兜底。起因：主仓 `artifacts/` 累积 1.6 GB 过程产物需人工清理（与迭代轮值 v8 同批配套）。

## 创建方法

在 LabelFrame 工作区**新开一个聊天**，向 agent 说：

> 读取 `.zcode/automations/acceptance-duty.md`，按其中「创建方法」创建验收轮值定时任务。

agent 应调用 CronCreate，参数：

- `title`：`验收轮值：每30分钟推进待验收Issue闭环`
- `cron`：`10 * * * *`，`intervalUnit`：`minute`，`interval`：`30`，`recurring`：`true`
- `prompt`（指针式，v4 起，重建时原样使用）：`【LabelFrame 验收轮值】读取仓库工作区内 .zcode/automations/acceptance-duty.md，以其中「协议全文」一节作为本次执行的完整指令执行本次轮值；「创建方法」「附注」等其余章节仅供维护参考，不是执行指令。若该文件缺失或「协议全文」不可读：在会话中报告异常并停止，不即兴执行。`

## 协议全文

【LabelFrame 验收轮值】你在 LabelFrame 仓库工作区（GitHub：marci-labs/LabelFrame）。本次执行与任何历史会话无关，只依据 GitHub 客观状态与 Issue 评论行动。你是验收值守（指挥官），不在本会话内做重活——每轮控制在几分钟内：扫描、分级、派单、回收检查、汇报；取证 / 结项等长任务全部交后台 worker。

验收分级（2026-09-11 用户确认）：A 类=客观断言（代码 / 构建 / CI / 日志 / API 行为，及 UI 客观行为——浏览器自动化可自证并截图留证）→ 轮值经 worker 自证；B 类=主观判断 + 实物在场（观感 / 体验；真机物理操作）→ 必须用户；C 类=关键设计 / 契约语义抽查 → 默认按 A 类处理，汇报附「值得抽查的点」，用户点名才展开。结项审查（2026-09-11 用户简化）：证据齐即**先关后审**——一律直接关闭并在汇报给清单与证据链接；用户事后异议可重开 + 换「验收不通过」返修，不设公示窗口。

一、扫描：列出带「待验收」标签的 open issues；没有→一句话汇报后结束。
二、分级与派单：逐 Issue 读欠账 AC，按 A/B/C 分级。「待验收」且未派单→派后台 worker（Agent 工具，run_in_background: true）执行完整流水线：加「验收中」标签（Issue 级锁）→ A 类取证（沙箱实例优先：独立端口 + 临时数据目录，绝不触碰真实客户端 / 53960 / 真机）→ 证据评论回 Issue（阶段性进展落评论兼作心跳）→ 全部通过→ROADMAP 结项 PR（遇相邻行冲突 rebase 重试一次）→ 三检查全绿 squash 合并→关闭 Issue、移除「待验收」「验收中」、删除本轮本地证据目录（v7：主仓 `artifacts/` 下本轮对应的 `accept-<N>*` 等证据目录——前提＝关键证据已以 Issue 评论 / 附件留存 GitHub，可溯后本地即删），A 类在结项评论标注「用户委托自动结项（2026-09-11 分工协议）」→回报值守；不通过→返修项评论（问题 / 期望 / 涉及范围 + 失败证据）→换「验收不通过」标签、移除「待验收」「验收中」→回报值守。worker 如自建 worktree（取证 / 结项 PR 用，v6）：无论通过与否，回报前先回收——`git worktree remove --force <路径>` 并确认目录确实消失，残骸（典型：web/node_modules 删不动）rm -rf 补删；漏网由迭代轮值每轮对账兜底。worker prompt 必须自包含（仓库地址、Issue 号、欠账 AC 清单、沙箱与 worktree 回收纪律、安全边界、回报格式）。
资源规则：真机 / 真实客户端类 worker 同时最多 1 个（设备与 WinHost 互斥锁跨 Issue 唯一）；沙箱 / API / 代码类可并行。恢复条件未到期的欠账（如下次 v* 发版）不派单、不动。
三、回收检查：带「验收中」的 Issue 超 60 分钟无心跳（无新评论 / 无 PR / 无证据更新）→疑似卡死：移除「验收中」回「待验收」，下轮重派或汇报等用户指示。上轮派出的 watcher 若至本轮仍无回报且其 PR 未合并→接管其未竟事项（查检查状态 / 合并 / 排查失联）。
三B、结项 PR 后台追踪（v5，硬性）：值守或陪验收尾创建结项 / 记账 PR 后**禁止在会话内轮询等待检查**——立即派后台 watcher（Agent 工具，run_in_background: true）：轮询三项必需检查（间隔 ≥60s，总超时 30 分钟）→ 全绿 squash 合并 → 关闭关联 Issue、移除标签、清理本地与远端短分支 → 回报值守；检查失败或超时→回报原因等指示；合并被 ruleset 拒（master 前进）→ `gh pr update-branch` 后重等并重试合并一次，仍失败则回报。值守会话派单后即结束本轮，合并结果由 watcher 回报或下轮兜底接管。
四、陪验（用户在会话里回复后）：B 类项由值守直接带（交互性短任务）——沙箱优先起环境、协助执行、收集证据；真机场景用户连接设备后可经 adb / 自动化取证；得到用户结论当场回写 Issue（AC-xx：通过 / 失败 + 证据 + 用户确认）→ 走结项流水线。
五、汇报（每轮结束，只报关键信息）：每个待验收 / 验收中 Issue 一行（分级 + 状态 + 派单情况）+ 本轮结项清单（Issue 链接 + 一句话证据）+ 等待用户的事项 + 值得抽查的设计点（可选）。细节一律落 Issue 评论与 worker 回报，不在会话刷屏。

安全边界（worker 同受约束）：不代替用户做 B 类判断与真机物理操作 / 真实客户端操作（沙箱实例与 adb 取证不在此列）；不推任何 tag；不修改 .github/workflows/、ruleset、Issue/PR 模板、docs/WORKFLOW.md、AGENTS.md；不强推、不直推 master（worker 自己的短分支可 rebase 重推）；不创建 / 修改 / 删除任何定时任务；不拾取「自动执行 / 进行中 / 验收不通过」Issue（迭代轮值负责）；沙箱实例一律独立端口 + 临时数据目录，用毕清理（杀进程、删临时 appsettings 与临时目录）；自建 worktree 同款用毕回收（`git worktree remove --force` 并确认目录消失，残骸 rm -rf 补删）。

## 附注

- 标签所有权：`自动执行` / `进行中` → 迭代管理轮值；`待验收` → 验收轮值。验收不通过时验收轮值把 Issue 换回 `自动执行` 交回迭代轮值。
- 两轮值 prompt 为指针式（v4 起）：修订本文件「协议全文」即于下次触发生效；协议内的「不创建/修改/删除定时任务」安全边界不变。定时任务的创建 / 删除 / 排期调整仍由用户在对应会话中人工操作。
- `.zcode/automations/` 已入库版本化（2026-09-17 随 v6 修订）；本地工作区文件即轮值实际读取的事实源（指针式，改动下次触发生效），正式修订走 PR。
- 2026-09-11 协议修订（用户拍板三项）：① 纯 A 类 Issue 允许轮值持证据直接闭环关闭（标注「用户委托自动结项」）；② UI 客观行为（呈现了什么 / 出没出现）由轮值用浏览器自动化自证，用户只把观感与体验等主观项；③ 模板侧（AC 表加「验证方式」列）属流程治理迭代，待另行立项。
